# Windows PE modules a game commonly imports and this bundle does not ship.
# Format: `<kind> <module-stem>`, `#` starts a comment.
#
# This file is a to-build list, not a wish list: every entry below was checked
# against app/Madeira/{arm64ec,aarch64}-windows and none of them is there.
# Only ~120 DLLs ship, and that set was never a compatibility decision: it is
# the transitive closure of the test binaries' imports (fourteen of the files
# in app/Madeira/arm64ec-windows are wine's own test exes) plus what DXMT
# needs. Every module below is one a real title links against, and a missing one
# is not a degraded feature -- LoadLibrary fails, the title's startup path
# aborts, and the user sees a game that does not start. This is the gap Winlator
# closes with its components, and the list is taken from that:
# wincomponents/wincomponents.json ships Microsoft's DirectX redistributable
# (direct3d, 30 MB compressed: d3dx9_24..43, d3dx10_33..43, d3dx11_42/43,
# d3dcsx_42/43, d3dcompiler_33..47), DirectMusic, DirectShow, DirectPlay,
# XAudio2, the 2005/2010 VC++ runtimes and the WMV decoders, and installs each
# into system32 with a DllOverrides `native,builtin` entry.
#
#   wine    -- Wine builds it (dlls/<module>), so scripts/build-wine-pe-modules.sh
#              can produce it from the pinned tree; a missing one is a defect.
#   native  -- Wine does not implement it at all; the only source is Microsoft's
#              redistributable. Reported, never failed: these need a component
#              like app/Madeira/x86_64-vcruntime, not a build.
#
# The two halves are complements, not alternatives. The aliases in
# app/Madeira/DLLAliases.h paper over the d3dx9/d3dcompiler generations with the
# modules that are already shipped, which is free and immediate; building the
# real modules gives a title the implementation it was linked against, and both
# routes stay open in the directory that wins (the runtime never overwrites).
